## What It Does

A single-page web tool aimed at prospects. The user describes a manual, repetitive process in plain language, and the tool returns a structured automation blueprint — generated by AI — laying out how that process could be automated. It is built as a top-of-funnel lead-generation asset: the prospect gets immediate, concrete value, and the page ends with a soft call-to-action to book a scoping call.

The value-return mechanic is the point — someone who sees their own painful process turned into a clear automation plan in seconds is a warm lead.

---

## System Components

| Component | Description |
|-----------|-------------|
| Frontend | Single-file HTML/CSS/JS form on GitHub Pages |
| Orchestration | Make.com scenario — webhook receives the process description |
| AI | Groq (llama-3.3-70b-versatile) — generates the blueprint |
| Response path | Make Webhook Response returns the blueprint to the page |
| CTA | "Book Discovery Call" mailto link to scope and price the work |

---

## Architecture

    User describes a manual process → submits form (GitHub Pages)
    → POST to Make.com webhook
    → Set Variable module builds the prompt (single unbroken line)
    → HTTP module calls Groq with the structured prompt
    → JSON parser extracts the blueprint
    → Webhook Response returns it to the frontend (CORS headers set)
    → Page renders the blueprint + soft CTA to book a call

---

## Key Design Decisions

- Make.com Webhook Response used to return the result synchronously to the browser — so the prospect sees the blueprint on the page, not in an email
- Groq free tier for zero-cost inference during demo/lead-gen use
- Soft CTA at the end — value first, ask second; the blueprint is given freely, the call is offered
- Single-file frontend on Pages — no build step, no hosting cost, easy to iterate

## Rebuild-From-Prompt Protocol

**Accounts required:**
- [ ] GitHub (Pages enabled)
- [ ] Make.com (webhook + HTTP + Webhook Response)
- [ ] Groq (free tier) — groq.com

**Steps:**
1. Build the single-file HTML form (process description input + results area)
2. Create a Make.com scenario triggered by a webhook
3. Add a Set Variable module to build the Groq prompt as one unbroken line
4. Add an HTTP module calling Groq with the prompt
5. Parse the JSON response and return it via a Webhook Response module
6. Set the response headers: `Access-Control-Allow-Origin: *` and `Content-Type: application/json`
7. Toggle "Immediately as data arrives" ON so the scenario responds live
8. Test from the frontend end to end

---

## Known Constraints

- Make.com free tier has a monthly operations limit
- Groq free tier is rate-limited — fine for demo volume, not high traffic
- The Set Variable prompt must be a single line with no special characters — nested JSON or line breaks cause control-character errors when Make interpolates it into the HTTP body
- "Immediately as data arrives" must stay ON, or the webhook won't respond without a manual run
- No authentication — open to anyone with the URL
